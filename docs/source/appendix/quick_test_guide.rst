Quick Test Guide - Earthquake Catalogue Fixes
=============================================


🎯 What Was Fixed
----------------


1. **Geographic Filter** - Now correctly filters events by latitude/longitude bounds
2. **Focal Mechanisms** - Beach ball diagrams now display correctly for M ≥ 5.0 events

📊 Test Data Available
---------------------


- **3 catalogues** (``test-data/north-island-catalogue.json``, ``south-island-catalogue.json``, ``deep-events-catalogue.json``), 1,000 events each, generated by ``scripts/generate_test_data.py`` — all New Zealand regions: North Island, South Island, and deep subduction events
- Magnitudes are drawn from a doubly-truncated Gutenberg-Richter distribution (b ≈ 1, M1.0-M7.5), so **M ≥ 5.0 events — and the focal mechanisms attached to them — are rare to essentially absent** in a given 1,000-event batch (expected well under 1 per catalogue). This is realistic short-catalogue behaviour, not a bug: don't expect freshly generated data to contain beach ball diagrams.
- By default, **60-80% of events per catalogue are intentionally invalid** (missing fields, out-of-range coordinates/magnitude/depth, malformed or future timestamps, wrong field types) to stress-test upload validation and data-quality reporting. A further ~15% of the remaining events are valid but carry a deliberate cross-field anomaly (very shallow depth with a very large magnitude).

3. Test Focal Mechanisms
^^^^^^^^^^^^^^^^^^^^^^^^


Magnitudes in the generated data follow a realistic Gutenberg-Richter
distribution, so M ≥ 5.0 events — and the focal mechanisms attached to them
— are rare to absent in a given 1,000-event batch. Don't rely on this
generator's output to reliably show beach ball diagrams; to reliably see one,
import a real GeoNet baseline catalogue instead (see
:doc:`/appendix/geonet_baseline_setup`), which includes genuine large events when they
exist in the requested time range.

If a M ≥ 5.0 event is present in your data:

1. Click on the catalogue
2. Go to map view
3. Filter for magnitude ≥ 5.0
4. Look for a beach ball diagram on the map
5. Click on it to see fault plane details

**Expected fault type by catalogue** (from the generator's tectonic-setting parameter):
- North Island & Deep Events: Thrust faulting (subduction, compressional quadrants)
- South Island: Strike-slip faulting (different pattern)

📁 Catalogue IDs
---------------


Catalogue IDs are UUIDs assigned by the API when each file is imported —
they are **not** fixed values produced by the generator. After importing,
find them either in ``scripts/import_test_catalogues_api.sh``'s output (it
prints ``Created catalogue with ID: <uuid>`` for each file) or via
``GET /api/catalogues`` / the ``/catalogues`` page.


🔍 Verification Queries
----------------------


This platform stores data in MongoDB, not SQL, so there is no
``merged_catalogues`` / ``merged_events`` table to query directly. Verify
imports through the application instead:

- **Event counts by catalogue**: visit ``/catalogues`` (or ``GET /api/catalogues``), which lists each catalogue's name and ``event_count``.
- **Events with focal mechanisms**: open a catalogue's map view and look for beach ball markers (likely none in freshly generated data — see the Test Focal Mechanisms section above).


✅ Success Criteria
------------------


- [ ] Geographic filtering returns only events within the specified bounds
- [ ] When a batch happens to contain a M ≥ 5.0 event, its beach ball diagram appears on the map and clicking it shows fault plane details (rare by design — see the Test Focal Mechanisms section above)
- [ ] A region with a mechanism present shows the fault type matching its tectonic setting
- [ ] Each import's response includes a ``validationReport`` with ``successfullyImported`` and ``totalSubmitted`` counts — since the generator marks 60-80% of each file's 1,000 events invalid by design, expect a similar share of each import to fail validation rather than all 1,000 succeeding

🔄 Re-import Data
----------------


If needed, regenerate the JSON files and import them through the
application's authenticated API:

.. code-block:: bash

   # Regenerate test-data/*.json (fixed random seed, so re-running produces
   # the same data every time)
   python3 scripts/generate_test_data.py

   # Import all three files via POST /api/catalogues, signed in as an
   # existing Editor-or-Admin account
   export CATALOGUE_API_EMAIL=you@example.com
   export CATALOGUE_API_PASSWORD='...'
   bash scripts/import_test_catalogues_api.sh


🗑️ Clean Up
-----------


To remove the test catalogues, use the application: delete each one from
its card on the ``/catalogues`` page, or call
``DELETE /api/catalogues/<catalogue-id>`` for each catalogue ID you noted
during import.
